# decide-extract-sdk

Contract-first SDKs for the Decider-Extractor API, generated by [Fern](https://buildwithfern.com)
from a single OpenAPI 3.1 contract.

| Language | Package | Where it lands |
| --- | --- | --- |
| TypeScript | `@dsainvg/decide-extractor-sdk` | npm |
| Python | `dsainvg-decide-extractor-sdk` | PyPI |
| Ruby | gem (see `fern/generators.yml`) | GitHub Release asset |
| Rust | crate (see `fern/generators.yml`) | GitHub Release asset |
| Java | jar (see `fern/generators.yml`) | GitHub Release asset |
| .NET | nupkg (see `fern/generators.yml`) | GitHub Release asset |
| C++ | none, call the HTTP API | - |

The contract is the source of truth. Everything in `packages/` is generated from
`fern/openapi/openapi.yml` and should never be edited by hand.

## Repository layout

```text
fern/
  fern.config.json         Fern project config (pins the CLI version)
  generators.yml           generator definitions, one per target language
  openapi/openapi.yml      THE CONTRACT, including the released version
packages/
  sdk-ts/  sdk-py/  sdk-ruby/  sdk-rust/  sdk-java/  sdk-csharp/
                          generated clients, committed to git

.github/workflows/

  release.yml              tag -> registries -> GitHub Release
  docs.yml                 docs site -> Cloudflare
```

## Requirements

- Node.js 20+ (developed on 24)
- Docker, for `fern generate --local`, which is how all generators run
- Python 3.9+ and [uv](https://docs.astral.sh/uv/), Ruby 3.3+, Rust stable, JDK 17+ with
  Maven, or .NET SDK 8 for the client you care about. Missing toolchains are skipped, not
  failed.

## First checkout

```bash
npm install
npm run fern:check        # validate the contract and generator config
npm run fern:generate     # writes packages/* (needs Docker)
git add packages && git commit -m "chore: generate SDKs"
```

Until that first generation is committed, the `Generate SDKs` CI job fails on drift. That is
intentional: the repo should never contain clients that disagree with the contract.

## Changing the API

1. Edit `fern/openapi/openapi.yml`.
2. Bump `info.version` if the change is releasable (`npm run version:bump -- patch`).
3. `npm run fern:generate`.
4. Commit the contract **and** `packages/` in the same commit.

CI enforces steps 3 and 4: `Generate SDKs` regenerates from scratch and fails if the result
differs from what is committed.

## Versioning and releases

One version, one source: `info.version` in the contract. It is stamped into every generated
package and must match the git tag.

```bash
npm run version:bump -- minor     # edits the contract, regenerates, prints next steps
git add fern/openapi/openapi.yml packages
git commit -m "release: v0.4.0"
git tag -a v0.4.0 -m "v0.4.0"
git push origin main --tags
```

Before anything is published, a gate runs every check that must hold: tag matches the
contract, the contract validates, regeneration is clean, every package carries the right
version, every package builds and produces an artifact, and the registry credentials are
present.

```bash
npm run release:check
```

Pushing the tag then publishes the TypeScript client to npm and the Python client to PyPI,
builds the Ruby, Rust, Java and .NET packages, attaches all of them plus the npm and PyPI
tarballs to the GitHub Release, and opens it.
Runbooks: [PUBLISHING.md](PUBLISHING.md) for tokens, [RELEASING.md](RELEASING.md) for the
release procedure.

## Scripts

| Command | What it does |
| --- | --- |
| `npm run fern:check` | Validate the contract and Fern configuration |
| `npm run fern:generate` | Regenerate every SDK at the contract version |
| `npm run fern:check:drift` | Regenerate and fail if the committed SDKs are stale |
| `npm run version:print` | Print the contract version |
| `npm run version:bump -- patch\|minor\|major\|x.y.z` | Bump the version and regenerate |
| `npm test` | Build and test every generated SDK |
| `npm run test:ts` / `:py` / `:rb` / `:rs` / `:java` / `:cs` | One language only |
| `npm run release:check` | The full pre-publish gate |
| `npm run build:artifacts` | Build every package and collect artifacts into `release-artifacts/` |
| `npm run docs:build` / `docs:serve` | Build and preview the documentation site |
| `npm run ci` | Everything CI runs, locally |

## Required repository secrets

Two, and only two:

| Secret | For |
| --- | --- |
| `NPM_TOKEN` | npm. Automation token with publish access to the `@dsainvg` scope |
| `PYPI_API_TOKEN` | PyPI, optional. Without it, trusted publishing (OIDC) is used |

The docs site deploys from the `sites` branch using the automatic `GITHUB_TOKEN`, so there is
no Cloudflare credential in this repository. Details: [PUBLISHING.md](PUBLISHING.md).
